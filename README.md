# 多评委评分校准（Multi-Judge Score Calibration）

一个用于校准多评委评分偏差、识别人名前后名次反转并支持人工裁决审计的 Web 应用。

- **后端**：FastAPI（Python 3.12）+ SQLite，数据**仅保存在 Docker 卷**中
- **前端**：原生 HTML / CSS / JavaScript（无构建步骤、无框架）
- **算法**：按评委（或评委×项目）做 **中位数 + MAD** 稳健标准化
- **审计**：每条评分可标记「保留原分 / 采用校准分」并填写理由，排名实时重算，可导出含完整审计明细的 CSV

---

## 一条命令启动

```bash
docker compose up --build -d
```

启动后访问：

| 入口 | 地址 | 端口 |
|---|---|---|
| **Web 页面** | http://localhost:8000 | 8000（可用 `APP_PORT` 改宿主机端口） |
| **API** | http://localhost:8000/api/…（统一前缀 `/api/sessions/{会话ID}`） | 同上 |
| **交互式 API 文档** | http://localhost:8000/docs | 同上 |

页面入口：打开后在顶部「① 数据导入」卡片中操作——

- **上传 CSV（替换导入）**：沿用原有方式，整体替换当前会话数据；
- **合并导入（预览差异）**：选择 CSV 后先展示四类记录的逐条差异（新旧分数 + 受影响裁决），确认后单事务落库，取消不改数据；
- **载入示例数据**：一键加载内置样本。

导入后向下滚动即可看到各功能卡片，其中 **「⑤ 评委排序分歧」** 面板按项目 × 评委对统计原始分排序的同向/逆向/同分情况，点开分组行可查看逆向选手对的双方原分（只读，不受校准范围与裁决影响）；**「⑥ 评委严宽差异诊断」** 面板仅用原始分，在每对评委的共评记录上计算分差中位数与共评数，以共评数为权重逐连通分量拟合评委相对偏移量（各分量内均值零、不跨分量比较，无共评边的评委不可估计），并列出评委对的观测分差、拟合分差与残差（只读，导入或合并后实时刷新）；**「⑨ 补评分派」** 面板可在只读模式下预览补评任务的最大分派方案（不写入评分或裁决）；**「⑪ 项目权重临界点分析」** 面板在排名页选择项目与倍率上限后，枚举该项目倍率从 0 连续变化过程中所有选手总分相等的临界倍率与各区间名次（只读实时重算）；**「⑫ 同评委可比对照」** 面板在当前最终分上对每对选手逐项目只取双方共同评分的评委求同一评委集合的均分并汇总差值，标出与全量最终总分方向反向的选手对（只读实时重算）；**③ 排名页内的「晋级门槛检查」** 面板可为一个或多个项目填写最终项目均分最低线（可选填最终总分线），实时判定每位选手达标 / 未达标 / 数据不足（缺失门槛项目不按 0 分处理，只读不落库，评分、裁决或范围变化后自动失效重算）；**③ 排名页内的「待补评分名次边界」** 面板可选择一个项目、目标评委人数与待补评分的最终分上下限，把每位选手在该项目补足至目标人数（待补分独立取区间内任意值），重算项目均分与最终总分区间并给出可达到的最好 / 最差竞赛名次（只读实时重算）。

API 统一以 `/api/sessions/{会话ID}` 为前缀（浏览器会在 `localStorage` 自动生成会话 ID），交互式文档见 **http://localhost:8000/docs**。

停止：

```bash
docker compose down          # 停止，保留数据卷
docker compose down -v       # 停止并删除数据卷（清空全部数据）
```

> 若 8000 端口被占用，可修改端口（见下文「配置」）。

## 功能一览

1. **CSV 导入（替换）**：上传包含 `选手、评委、项目、分数` 的 CSV（支持中英文表头，自动识别 UTF-8 BOM），**整体替换**当前会话的全部评分，并清空旧裁决与批处理规则。
2. **评分数据合并导入（预览 → 确认/取消）**：在「上传 CSV」旁提供独立的**合并导入**入口。上传后先调用只读预览接口，按「选手 + 评委 + 项目」三元组把记录分为四类并逐条展示：
   - **新增**：新文件有、当前会话没有；
   - **未变**：两边都有且分数相同（保持不动）；
   - **分数变更**：两边都有但分数不同，逐行显示**旧分数 → 新分数**；
   - **仅存在于当前会话（将删除）**：新文件中缺失的记录。

   预览逐行列出新旧分数以及该行**将受影响的裁决**（分数变更/删除行若存在旧裁决会标记「旧裁决将清除」并展示其原内容；未变行的裁决标记「保留」），顶部汇总各类条数与将清除的裁决数。预览**完全只读**：不点确认、或点「取消」都不会改动任何数据。**预览时服务端会保存一份会话专属的待合并快照（解析后的新记录 + 当前评分/受影响裁决基线），并返回一个不可猜测的一次性标识（256 位随机 token）；确认请求只携带该标识**，因此无法把未预览的记录塞进确认请求（例如预览显示 80→81，确认时无法改写成 99）。确认时在**同一数据库事务**内先原子消耗标识（条件 UPDATE），再按标识取回服务端快照、重建差异并核对当前评分与受影响裁决基线，通过后才落库：更新、删除、新增与旧裁决清除全部在该事务中提交（任一步失败整体回滚）；**未变记录（含其裁决）与已保存的批处理规则始终保持不动**。标识无效、不属于本会话、已使用（含重复确认）、已过期，或预览后评分/受影响裁决被其他操作改动（含相关裁决被新增、修改或删除）时返回 `409` 要求重新预览，且**不写入任何评分或裁决**；同一会话再次预览会使旧标识立即失效。
4. **一键载入示例数据**：内置 6 位选手 × 4 位评委 × 3 个项目（72 条评分），其中包含刻意设置的宽松/严苛评委与人名前后名次反转（S03/S04 名次互换）。
3. **稳健标准化**
   - 对每个校准分组计算中位数与 MAD（median absolute deviation）：
     ```
     Z = (原始分 − 分组中位数) / (分组MAD × 1.4826)
     校准分 = 全局中位数 + Z × 全局MAD(×1.4826)
     ```
   - 系数 1.4826 使 MAD 在正态分布下是标准差的一致估计量；分组无离散度（MAD=0）时取 Z=0。
   - 校准范围可在 **「按评委（跨项目汇总）」** 与 **「按评委×项目」** 间切换。
5. **合成项目总分**：选手每个项目取各评委打分的均值，项目总分为各项目均值之和。
6. **名次反转识别**：列出所有在原始排名与校准排名之间优胜关系反转的选手对及分差。
7. **双选手对比**：从当前数据中选择两名选手，查看双方**原始、校准与最终总分差**（A−B）与最终名次，并按项目列出双方在各项目的得分（项目内评委均分）与三类差值；逐项目汇总**领先 / 持平数量**（按最终分，并附按原始分、校准分统计）。某选手在某项目没有任何评分时标为**「无数据」**，不按零分参与差值计算或胜负统计。对比结果每次都由当前评分实时计算，**不另存任何评分**，切换校准范围或修改人工裁决后自动刷新。
8. **评委排序分歧（只读，仅基于原始分）**：按**项目 × 评委对**分组，仅取两位评委**都打过分**的选手（共评选手），枚举全部选手对并依**原始分**归类——**同向**（双方均非同分、排序方向一致）、**逆向**（双方均非同分、排序方向相反）、**单方同分**（恰有一位评委给同分）、**双方同分**（两位评委都给同分）。共评选手少于 2 名的分组标为**「样本不足」**，不给出分歧率；仅**双方均非同分**（同向、逆向）的选手对计入可比较对数，**逆向占比 = 逆向对数 / 可比较对数**。面板列表展示各分组的四类数量与逆向占比（样本不足分组沉底），**点行展开可查看其中逆向选手对的两位评委给两位选手的原始分及各自更看好谁**。结果随上传、合并导入**实时刷新**，全程只读，**不受校准范围切换与逐项/批处理裁决影响**。
9. **逐项人工裁决**：每条评分可选择「采用校准分」（默认）或「保留原分」并填写理由；保存后**最终排名实时重算**（原始与校准排名始终并列展示）。
10. **评分裁决规则批处理**：按**评委、项目、原始分区间、校准分区间**组合条件（均留空即不限，区间为闭区间）批量设置「保留原分 / 采用校准分」与理由模板（支持 `{judge}`、`{item}`、`{raw}`、`{calibrated}` 占位符），并为每条规则指定**优先级**（数字越小越优先；数字相同时按规则顺序前者优先）。
   - 先点**预览**：系统逐条评分匹配全部规则，返回每条规则的**命中数、未命中数、多规则冲突数、胜出数**，并按优先级为每个评分裁决出唯一结果；同时给出「预计实际变更条数」。**预览完全只读，不保存规则、不写裁决、不改动会话。**
   - 确认后点**应用**：规则与全部裁决在**同一个数据库事务**中批量写入（任何一步失败整体回滚），返回写入条数、实际变更条数并自动刷新最终排名；未命中任何规则的评分保持现有裁决不变。规则随会话持久化（重新上传数据会清空旧规则），也可「仅保存规则」稍后再应用。
11. **导出审计 CSV**（UTF-8 BOM，Excel 可直接打开），包含五个部分：
   - 【明细】逐条评分：原始分、分组中位数/MAD、稳健 Z、校准分、采用选择、最终分、理由
   - 【汇总】选手原始/校准/最终总分与名次、名次变化
   - 【反转】标准化前后名次反转的选手对
   - 【校准参数】各分组中位数与 MAD
   - 【批处理裁决规则】已持久化规则的条件、优先级、裁决与理由模板
12. **排名稳定性实验（临时模拟，不保存）**：选择**临时排除一名评委或一个项目**，系统按当前校准范围重新拟合校准参数并重算原始、校准、最终总分与竞赛名次；逐位展示每位选手相对基线的三类名次变化、三类总分变化以及被移除的评分条数，并汇总名次上升/下降人数、最大总分波动等。实验结果仅保存在浏览器当前页面，**不会写入会话裁决或数据库**，可随时「清除结果，恢复基线」；上传数据、切换校准范围或修改裁决时实验结果会自动失效。
13. **补评分派（只读预览，不写入评分或裁决）**：以当前会话中**已有评分**的「选手 × 项目」组合为**需求单元**，统一设定每单元**目标评委人数**，并分别设定**各评委本轮可接任务数**。只有**已给该项目打过分（任意选手）、但尚未给该单元打分**的评委才有资格接该单元；扣除已有评分后，系统在评委容量与每单元缺口约束下求**分派任务总数最大**的方案（最大流），候选存在多个最优并列方案时按固定的**评委 → 项目 → 选手**次序稳定选取，保证同一输入永远得到同一结果。预览逐条展示**评委、选手、项目**的分派明细，并汇总**各单元未满足数量**（含合格评委名单）；上传、合并或载入新数据后旧预览自动失效，需重新生成。全程只读，**不写入任何评分或裁决**。
14. **清空会话**：一键删除当前浏览器会话的全部评分、裁决、批处理规则与理由（数据仅存在容器卷，删除不可恢复）。
15. **项目权重临界点分析（只读）**：在**③ 排名页**选择一个项目与倍率上限（1～5），以当前校准范围及逐项裁决形成的**项目最终均分**为基础，令该项目倍率从 **0** 连续变化到上限、其余项目倍率恒为 **1**：
    - 每位选手总分是倍率 `w` 的线性函数 `该项目最终均分 × w +（最终总分 − 该项目最终均分）`，选手缺失该项目时**按 0 贡献**（斜率为 0）；
    - 枚举闭区间 `[0, 上限]` 内**所有选手总分相等的临界倍率**（两两直线交点），**同一数学交点的浮点偏差自动合并**为一个临界点（多选手同时并列），**可表示且真实不同的近邻交点分别列出**（归并/端点吸附/区间切分共用 1e-12 级相对容差，只吸收浮点误差），**始终并列（直线重合）的选手不产生交点**；斜率与截距按计算结果**精确比较**（完全相等才算平行/重合），不随分数尺度放大容差——大数总分下可表示的真实交点照常列出并给出交点前后名次，截距不同的平行线不会被误判为始终并列；
    - 依次展示每个**临界点**（含恰好落在端点 0 / 上限的交点，带端点标记）及**每对相邻临界点**构成的**开区间中点**处的**竞赛名次（1224）与总分**，并明确标出临界点处**并列的选手**（并列组只含该点真实相等的选手）；彼此接近的倍率按足够区分的精度显示；
    - 结果**完全只读**，每次请求都由当前数据实时重算，**不写入评分、裁决或会话**；评分、裁决或校准范围变化后前端自动标记旧结果过期并重新计算。
16. **晋级门槛检查（只读，排名页内）**：在**③ 排名页**为一个或多个项目填写**最终项目均分最低线**，并可选填写一条**最终总分线**，系统即基于当前校准范围与逐项裁决形成的最终均分/总分实时判定每位选手：
    - **达标**：所有被设门槛项目都有评分且最终均分不低于对应最低线（恰好相等视为达标），且（若设置总分线）最终总分不低于总分线；
    - **未达标**：门槛项目均有评分，但至少一项最终均分低于最低线，或总分低于总分线；结果逐条列出各项目最终均分（附门槛线）、最终总分与全部未达标原因（含具体差距）；
    - **数据不足**：**缺少任一被设门槛项目**的选手标记为数据不足并列出缺失项目，**绝不按 0 分处理**，也不再判定其总分线；未设门槛的项目缺失不影响判定。

    门槛仅保存在浏览器当前页面，可一键**清空门槛**；检查**完全只读、不落库**，评分、逐项（或批处理）裁决或校准范围变化后旧结果自动失效并以当前填写的门槛重新计算。
17. **待补评分名次边界（只读，排名页内）**：在**③ 排名页**选择一个项目、**目标评委人数**与**待补评分的最终分上下限**，系统沿用当前校准范围与逐项裁决形成的**已有最终分**，将每位选手在该项目的评分**补足至目标人数**（每条待补分可独立取闭区间内任意值），重算该项目的**均分区间**与每位选手的**最终总分区间**（其余项目保持现值；该项目尚无评分的选手按整区间补足）：
    - **最好名次**：本人总分取**上限**、他人总分取**下限**时的竞赛名次；**最差名次**：本人**下限**对他人**上限**；同分容差与主排名一致（1e-9）；
    - 若任一选手在该项目的**已有评分数超过目标人数**，整个请求被拒绝并指明选手；
    - 面板逐人展示**缺口**（目标 − 已有评分数）、当前项目均分、补足后项目均分区间、最终总分区间与可达到名次区间（最好 ~ 最差）。

    结果**完全只读、不落库**，每次请求实时重算；评分、裁决或校准范围变化后自动失效并以当前参数重新计算，也可一键清除结果。
18. **评委严宽差异诊断（只读，仅基于原始分）**：对每对评委，取两人**共同评过的「选手 × 项目」记录**（共评记录），计算原始分差（评委甲 − 评委乙）的**中位数**作为观测分差，并以**共评记录数为权重**，在评委关系图（节点 = 评委，边 = 有共评记录的评委对）上**逐连通分量**做加权最小二乘拟合，使各分量内评委相对偏移量的**均值为零**——偏移量只是分量内相对值（正 = 相对偏宽，负 = 相对偏严），**不跨分量比较**；没有任何共评边的评委标为**「不可估计」**。面板列出各评委**偏移量**与**共评覆盖量**（该评委参与的共评记录条数、共评评委数），以及每对评委的**观测分差、拟合分差与残差**（附加权残差平方和与最大绝对残差）。结果随上传、合并导入**实时刷新**，全程只读，**不受校准范围切换与逐项/批处理裁决影响**；另提供只读接口 `GET /api/sessions/{id}/judge-offsets` 单独获取。
19. **同评委可比对照（只读）**：在当前校准范围与逐项裁决形成的**最终分**基础上，对**每一对选手逐项目只取双方共同评分的评委**——分别求**同一评委集合**上的最终分均分（共同评委均分），两个均分使用完全相同的评委集合，从而剔除「双方参评评委不同 / 评委严宽不同」带来的偏差；再把各可比项目的均分差（A−B）**逐项求和**为**可比总分差**并给出**可比领先者**（差在 1e-9 内视为持平）。
    - 某项目**一方没有评分（缺项目）**或双方在该项目**没有任何共同评委**时，该项目标为**不可比**：列出原因与评委覆盖，**绝不按 0 分**计入，也不参与差值汇总；**全部项目都不可比**的选手对整对标为**不可比**（同样不按 0 分、不参与方向对照）。
    - 面板逐对列出**可比项目数、各项目共同评委覆盖（项目 × 共同评委数）、全量最终总分与方向、可比总分与可比领先者、两种口径的方向对照**；全量口径的领先、并列与反向一律以主榜**最终名次**为准——名次相同即「全量并列」（不构成反向），名次有先后时再与可比方向比较，可比总分方向与之**相反**的选手对标为 **⚠ 反向**并自动置顶（全量并列标为「全量并列」）。注意全量并列**不按全量总分差落入 1e-9 容差判定**：主榜并列组以组最高分锚定（形如 90、90−0.6e-9、90−1.2e-9 的名次为 1、1、3），组外两人的分差可能仍在容差内，但名次已有先后，不构成并列。
    - 点开任一行可**展开计算明细**：每个可比项目列出全部共同评委分别给双方的最终分与逐评委分差、共同评委均分及该项目差值，并附注双方各自的全量评委覆盖（仅一方参评的评委明确标注不参与同评委均分）；不可比项目说明缺项目的一方或双方各自参评但无交集的评委名单。
    - 结果**完全只读**，每次请求都由当前数据实时重算，**不写入评分、裁决或会话**；上传/合并导入、逐项（或批处理）裁决或校准范围变化后前端自动标记并重算。只读接口为 `GET /api/sessions/{id}/common-judge`。

## CSV 文件格式

必需 4 列，表头顺序任意，以下表头名均可识别（不区分大小写、忽略空格）：

| 字段 | 支持的表头（节选） |
|---|---|
| 选手 | `选手`、`选手编号`、`姓名`、`contestant`、`name` |
| 评委 | `评委`、`裁判`、`judge`、`juror`、`rater` |
| 项目 | `项目`、`赛项`、`环节`、`item`、`event`、`round` |
| 分数 | `分数`、`得分`、`评分`、`score`、`points` |

示例：

```csv
选手,评委,项目,分数
S01,评委甲,技术展示,6.85
S01,评委乙,技术展示,16.23
S02,评委甲,技术展示,7.31
...
```

校验规则：四列缺一不可；分数必须为数字；同一「选手 × 评委 × 项目」不允许重复；空行会被忽略。错误信息会指到具体行号。

### 两种导入方式对比

| | 上传 CSV（替换导入） | 合并导入（预览差异） |
|---|---|---|
| 入口 | 「上传 CSV（替换导入）」按钮 | 「合并导入（预览差异）」按钮 |
| 处理方式 | 整体替换，先清空再写入 | 只改差异：更新 / 新增 / 删除，未变不动 |
| 人工裁决 | 全部清空 | 仅分数变更、删除记录的旧裁决自动清除；未变记录的裁决保留 |
| 批处理规则 | 全部清空（评委/项目集合已变） | **保持不动** |
| 确认方式 | 上传即生效 | 先只读预览（服务端保存快照并发放一次性标识），**凭标识确认**后单事务落库；**取消不改任何数据** |
| 记录主键 | 重新生成 | 三元组「选手 + 评委 + 项目」匹配；变更/未变记录保留原行 id |

合并预览页面可按「全部 / 分数变更 / 新增 / 仅当前会话 / 未变」筛选，逐行查看旧分数、新分数与裁决影响。向一个尚不存在（或已清空）的会话做合并导入时，等同首次导入（全部为新增），会话将以顶部选中的校准范围创建。

## API 摘要

会话 ID 由浏览器在 `localStorage` 生成并随路径传递（`{session_id}` 为任意字符串）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/sessions/{id}/upload?scope=judge` | 上传 CSV（multipart `file`），**替换导入**：清空旧评分/裁决/规则 |
| POST | `/api/sessions/{id}/merge/preview?scope=judge` | 合并导入**只读预览**（multipart `file`）：按三元组返回新增/未变/变更/仅当前会话逐行差异、新旧分数、受影响裁决、汇总计数；服务端同时保存会话专属待合并快照并返回不可猜测的一次性标识 `token`（响应**不回传** `records`/`basis`）；不改评分/裁决，不创建会话 |
| POST | `/api/sessions/{id}/merge/confirm` | **确认合并**，仅接受 `{"token": str}`：同一事务内原子消耗标识 → 按标识取回服务端快照 → 重建差异并核对当前评分及受影响裁决基线 → 通过才更新/新增/删除并清除变更、删除行的旧裁决；未变记录与规则不动；标识无效/已使用/已过期或基线不匹配均返回 `409`（需重新预览）且不写入，任一步失败整体回滚；返回刷新后的完整分析 |
| POST | `/api/sessions/{id}/sample?scope=judge` | 载入内置示例数据 |
| GET | `/api/sessions/{id}/analysis` | 获取完整分析结果（分组参数、总分、名次、反转、逐条分数、`judge_disagreement` 评委排序分歧、`judge_offsets` 评委严宽差异诊断） |
| POST | `/api/sessions/{id}/scope` | 切换校准范围（`{"scope":"judge"\|"judge_item"}`） |
| PATCH | `/api/sessions/{id}/scores/{score_id}/decision` | 单条裁决（`{"use_raw":bool,"reason":str}`），返回实时重算结果 |
| POST | `/api/sessions/{id}/rules/preview` | 规则批处理**只读预览**（`{"rules":[...]}`），返回每条规则命中/未命中/冲突/胜出数、按优先级裁决的逐条结果与预计变更数；不落库 |
| GET | `/api/sessions/{id}/rules` | 获取已持久化的批处理规则（按顺序） |
| PUT | `/api/sessions/{id}/rules` | 仅保存规则集（不写任何裁决），传 `{"rules":[]}` 清空规则 |
| POST | `/api/sessions/{id}/rules/apply` | **单事务**保存规则并批量写入命中评分的裁决，返回写入/变更条数与刷新后的完整排名 |
| POST | `/api/sessions/{id}/stability` | 排名稳定性实验（`{"exclude_type":"judge"\|"item","exclude_name":str}`），返回基线 vs 排除后逐位名次/总分变化；只读，不落库 |
| POST | `/api/sessions/{id}/backfill/preview` | 补评分派**只读预览**（`{"target":int, "capacities":{"评委":n}}`）：以已有评分的选手×项目为需求单元，仅允许评过该项目但未评该单元的评委接单，返回最大分派方案（按评委→项目→选手固定次序稳定输出）、各单元未满足数量与评委容量使用；不写入评分或裁决 |
| GET | `/api/sessions/{id}/compare?a=甲&b=乙` | 双选手对比：原始/校准/最终总分差、最终名次、逐项目得分与差值、逐项目领先/持平汇总；缺评分项目标为无数据、不计入统计；只读，不落库 |
| GET | `/api/sessions/{id}/judge-offsets` | 评委严宽差异诊断（只读，仅原始分）：每对评委共评记录的分差中位数与共评数，以共评数为权重逐连通分量拟合评委相对偏移量（各分量内均值零、不跨分量比较），返回评委偏移量/共评覆盖量与评委对观测分差/拟合分差/残差；无共评边的评委不可估计；会话不存在或无评分返回 `404` |
| GET | `/api/sessions/{id}/common-judge` | 同评委可比对照（只读）：对每对选手逐项目只取双方共同评分的评委，分别求同一评委集合的最终分均分，再汇总各可比项目差值（A−B）与可比领先者；缺项目或无共同评委的项目及全不可比的选手对标为不可比、不按 0 分；全量领先/并列/反向以当前分析的最终名次为准（同名次才为全量并列、不构成反向，名次有先后再与可比方向比较），返回逐项目共同评委覆盖/均分/差值、可展开的逐评委明细与反向标记；会话不存在或无评分返回 `404` |
| POST | `/api/sessions/{id}/weight-thresholds` | 项目权重临界点分析（`{"item":str,"upper_bound":1～5}`）：该项目倍率从 0 连续变化到上限（其余项目恒为 1），返回区间内全部选手总分相等的临界倍率（同一数学交点的浮点偏差合并、真实不同的近邻交点分别列出、始终并列者不产生交点）、各临界点与每对相邻开区间中点处的名次/总分及交点并列选手（只含该点真实相等者）；缺失项目按 0 贡献；只读，不落库 |
| POST | `/api/sessions/{id}/promotion-check` | 晋级门槛检查（`{"item_thresholds":[{"item":str,"min_avg":number}, ...], "total_threshold"?:number}`，至少一条项目门槛）：基于当前校准范围与裁决返回每位选手 `pass`/`fail`/`insufficient_data`、各项目最终均分与门槛、最终总分/总分线判定及未达标原因（含差距）；缺失任一被设门槛项目为数据不足并列出缺失项目，不按 0 分、不判总分；项目不存在/重复、数值非有限数字返回 `400`，空门槛数组返回 `422`；只读，不落库 |
| POST | `/api/sessions/{id}/pending-rank` | 待补评分名次边界（`{"item":str,"target":int,"score_min":number,"score_max":number}`）：沿用当前校准范围与裁决形成的最终分，将每位选手在该项目补足至目标评委人数（待补分独立取闭区间任意值），重算项目均分区间与最终总分区间（其余项目保持现值），并按「本人上限 vs 他人下限 / 本人下限 vs 他人上限」给出可达到的最好/最差竞赛名次（同分容差与主排名一致）；任一选手该项目已有评分数超过目标、项目不存在、下限大于上限或数值非法返回 `400`，目标人数越界/非整数返回 `422`；只读，不落库 |
| POST | `/api/sessions/{id}/decisions/reset` | 清除全部裁决，统一恢复校准分 |
| GET | `/api/sessions/{id}/export` | 下载审计 CSV |
| DELETE | `/api/sessions/{id}` | 清空会话 |

自动生成的交互式 API 文档：`http://localhost:8000/docs`。

规则对象（`rules` 数组元素）字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `judge` / `item` | string 或 null | 精确匹配评委/项目；null 或空串表示不限 |
| `raw_min` / `raw_max` | number 或 null | 原始分闭区间，null 表示该侧不限 |
| `cal_min` / `cal_max` | number 或 null | 校准分闭区间（按会话当前校准范围计算） |
| `use_raw` | bool | `true`=保留原分，`false`=采用校准分 |
| `reason_template` | string | 理由模板，占位符 `{judge}`/`{item}`/`{raw}`/`{calibrated}`（`{raw}`、`{calibrated}` 保留两位小数） |
| `priority` | int | 优先级，数字越小越优先（0–1000000），同值按数组顺序前者优先 |
| `name` | string | 可选规则名，便于审计与导出 |

### 合并导入接口细节

**预览** `POST /api/sessions/{id}/merge/preview`：multipart 表单字段 `file`，CSV 解析规则与替换上传完全一致。响应：

- `counts`：`{"changed": n, "added": n, "removed": n, "unchanged": n}`，另有 `will_modify`（前三类之和）、`decisions_cleared`（变更/删除行中带旧裁决的条数）、`total_current`、`total_incoming`；
- `rows[]`：每行含 `status`（`changed`/`added`/`removed`/`unchanged`）、`contestant`/`judge`/`item`、`old_score`/`new_score`（不适用一侧为 `null`）、`score_id`（仅当前会话侧有）、`has_decision`、`old_use_raw`、`old_reason`、`decision_action`（`clear`=旧裁决将清除 / `keep`=裁决保留 / `none`=本无裁决）；
- `token`：不可猜测的一次性标识（256 位随机数的十六进制串）。预览解析出的新记录与当前基线快照（含受影响评分的裁决状态）**只保存在服务端**，响应不回传，客户端无从篡改；同一会话再次预览会使旧标识立即失效，未使用的快照保留 24 小时后过期。

**确认** `POST /api/sessions/{id}/merge/confirm`，JSON 只有一个字段：

```json
{ "token": "f3a1…（预览响应里的一次性标识，64 个十六进制字符）" }
```

- 确认时不接受任何记录、基线或范围参数：待合并内容以服务端快照为唯一来源，无法确认「未预览」的数据；会话尚不存在时以预览时选定（或默认 `judge`）的校准范围创建会话，已有会话保持当前范围；
- 整个处理在**同一个数据库事务**内完成：先以条件 UPDATE 原子消耗标识（同时取得写锁，保证并发的第二次确认不可能成功），再读取当前全部评分、按快照记录重建差异计划并核对基线（全部评分 + 受影响评分的裁决存在性/采用原分/理由），核对通过后才写入；
- `200`：返回与 `GET analysis` 同构的最新分析，并附 `merge_applied.counts` 与 `merge_applied.decisions_cleared`；
- `422`：请求体缺少 `token` 或类型/长度不合法；
- `409`：① 标识不存在、不属于该会话或已过期——「合并预览标识无效或已过期，请重新预览…」；② 标识已被使用（含重复/并发确认）——「该合并预览已用于确认…请重新预览」；③ 基线与当前库不一致（预览后评分或受影响裁决被其他操作改动）——「预览后当前会话数据已变化，请重新预览…」。三种情况都**不写入任何评分或裁决**；
- 仅基线不匹配导致的 409 会随事务回滚标识消耗（数据恢复一致后仍可用同一预览确认）；应用阶段异常整体回滚，标识同样保持未消耗；只有成功提交时标识才真正用掉。取消（不发确认请求）自然不改任何数据。

### 评委排序分歧结果结构

所有返回完整分析的接口（`analysis`、`upload`、`sample`、`scope`、`merge/confirm`、`decisions/*`、`scores/{id}/decision`、`rules/apply`）都带同构的 `judge_disagreement` 段，无需单独请求：

- `summary`：`groups`/`sufficient_groups`/`insufficient_groups`（项目 × 评委对分组数）、`common_contestant_pairs`（全部共评选手对）、`counts`（`concordant`/`discordant`/`one_tie`/`both_tie` 四类数量，仅汇总样本充足分组）、`comparable_pairs`（双方均非同分的对数）、`discordant_pairs`、`discordance_rate`（无可比较对时为 `null`）；
- `groups[]`：每个分组含 `item`、`judge_a`、`judge_b`、`common_count`、`sufficient`、`pairs_total`、`counts`、`comparable_pairs`（样本不足为 `null`）、`discordance_rate`（样本不足或无可比较对为 `null`），以及 `discordant_pairs[]`——每个逆向选手对给出两位选手名、两位评委分别给两人的原始分（`judge_a_score_of_a/of_b`、`judge_b_score_of_a/of_b`）与各自更看好的选手（`judge_a_prefers`/`judge_b_prefers`）；
- `category_labels` 给出四类的中文标签（同向/逆向/单方同分/双方同分），`min_common` 为样本充足阈值（2）。

### 评委严宽差异诊断结果结构

所有返回完整分析的接口（`analysis`、`upload`、`sample`、`scope`、`merge/confirm`、`decisions/*`、`scores/{id}/decision`、`rules/apply`）都带同构的 `judge_offsets` 段；也可通过只读接口 `GET /api/sessions/{id}/judge-offsets` 单独获取（结构相同）：

- `summary`：`judges`/`estimable_judges`/`non_estimable_judges`（评委总数 / 可估计 / 不可估计人数）、`components`（连通分量数）、`pairs`（有共评记录的评委对数）、`common_records`（共评记录总条数）、`weighted_residual_ss`（加权残差平方和 Σ 共评数 × 残差²）、`max_abs_residual`（最大绝对残差，无评委对时为 `null`）；
- `judges[]`（按评委首次出现顺序）：`judge`、`estimable`、`component`（连通分量编号，从 1 开始；不可估计为 `null`）、`offset`（分量内相对偏移量，正 = 相对偏宽、负 = 相对偏严，各分量内均值为零；不可估计为 `null`）、`coverage`（共评覆盖量 = 该评委参与的共评记录条数）、`partners`（共评评委数）；
- `components[]`：`id`、`judges`（分量内评委）、`pairs`（分量内评委对数）、`common_records`（分量内共评记录条数）；
- `pairs[]`（按分量、评委甲、评委乙排序）：`judge_a`/`judge_b`、`component`、`common_count`（共评数，即拟合权重）、`observed_diff`（观测分差 = 共评记录原始分差（甲−乙）的中位数）、`fitted_diff`（拟合分差 = 偏移量甲 − 偏移量乙）、`residual`（残差 = 观测 − 拟合）。

全部数字仅由**原始分**计算，不接收 decisions、不随 scope 变化；偏移量只在同一连通分量内可比，**不跨分量比较**。

### 同评委可比对照结果结构

只读接口 `GET /api/sessions/{id}/common-judge`（会话不存在或没有评分返回 `404`），响应：

- `scope` / `scope_label`、`tie_eps`（可比持平容差 1e-9）与四组中文标签：`status_labels`（可比/不可比）、`item_reason_labels`（一方缺该项目/无共同评委）、`direction_labels`（同向/反向/全量并列/不可比）、`leader_labels`（A 领先/B 领先/持平）；
- `summary`：`pairs`（选手对总数）、`comparable` / `incomparable`（可比 / 不可比对数）、`a_leads` / `b_leads` / `ties`（可比口径领先统计）、`reversed` / `same_direction` / `full_tie`（方向对照统计）、`comparable_item_total`（全部对的可比项目条数合计）、`incomparable_missing_item_pairs` / `incomparable_no_common_pairs`（整对不可比时按对统计的两类原因数，一对可同时计入两类）、`contestants` / `items`；
- `pairs[]`（无序选手对，A 为全量名次更靠前者）：`a`/`b`、`a_rank`/`b_rank`、`comparable`、`status`（`comparable`/`incomparable`）、`a_full_total`/`b_full_total`/`full_delta`/`full_leader`（全量口径领先者，**以当前分析的最终名次为准**：同名次为 `tie`）、`comparable_items`/`incomparable_items`、`a_comparable_total`/`b_comparable_total`/`comparable_delta`/`comparable_leader`（**同评委可比**口径，不可比时均为 `null`）、`direction`（`same` 同向 / `reversed` 反向 / `full_tie` 全量最终名次并列 / `incomparable` 不可比）与 `reversed` 布尔标记；
- `pairs[].items[]`：逐项目给出 `comparable` 与不可比时的 `reason`（`missing_item` / `no_common_judge`）、`missing_side`（缺项目的一方，双方都缺为 `null` 且 `both_missing=true`）、`a_has_item`/`b_has_item`、`common_judges`/`common_count`；可比项目另给 `a_avg`/`b_avg`（**同一共同评委集合**上的最终分均分）、`delta`（A−B）、`leader`、`a_judges`/`b_judges`（双方在该项目的全部评委最终分明细，含非共同评委）与 `a_full_avg`/`b_full_avg`（全量项目均分，供展开明细对照）。

所有差值均为**当前最终分**（应用逐项裁决后），随评分、裁决与校准范围变化实时重算；不可比项目与不可比选手对**绝不按 0 分处理**。

### 项目权重临界点分析结果结构

`POST /api/sessions/{id}/weight-thresholds` 的请求体为 `{"item": "项目名", "upper_bound": 3}`（上限取 1～5 的数字；项目不存在或上限越界返回 `400`/`422`，会话不存在返回 `404`），响应：

- `item` / `lower`（恒为 0）/ `upper_bound` / `scope` / `scope_label`；
- `contestants_missing_item`：在该项目没有任何评分的选手（其总分线斜率为 0，该项目按 0 贡献）；
- `always_tied_groups`：在整个区间**始终并列**的选手组——仅当两条总分线**确实重合**（斜率与截距的计算结果完全相等）才计入，这些选手**不产生交点**；
- `summary`：`contestants`（选手数）、`crossing_pairs`（区间内选手对相交次数）、`critical_points`（归并同一数学交点浮点偏差后的临界点数，真实不同的近邻交点分别计数）、`interval_midpoints`（相邻开区间中点数）；
- `entries[]`：按倍率 `w` 升序交错排列两类条目——
  - `kind="critical"`：`w` 为临界倍率，`boundary` 为 `start`（恰好 w=0）/`end`（恰好等于上限）/`null`（内部交点），`ties` 为该点并列选手分组（如 `[["S01","S02"], …]`，只含该点真实相等的选手，组内按交点处总分降序），`ranking` 给出全员竞赛名次、总分、该项目最终均分与「是否交点并列」标记；
  - `kind="midpoint"`：相邻临界点（含端点 0、上限）构成的开区间中点，`w`/`left`/`right` 标明中点与所属开区间，`ranking` 为该中点处的全员名次与总分。

### 晋级门槛检查接口细节

`POST /api/sessions/{id}/promotion-check` 请求体：

```json
{
  "item_thresholds": [
    {"item": "技术展示", "min_avg": 8.0},
    {"item": "艺术表现", "min_avg": 7.5}
  ],
  "total_threshold": 24.0
}
```

- `item_thresholds`：**至少一条**（空数组返回 `422`）；项目名会去除首尾空白，同一项目重复设线返回 `400`；项目必须存在于当前会话，否则返回 `400` 并列出可选项目。
- `min_avg` / `total_threshold`：必须是有限数字（不接受 NaN/Infinity/布尔值）；`total_threshold` 可省略或为 `null`，表示不检查总分线。
- 会话不存在返回 `404`；会话存在但没有评分返回 `404`。

响应：

- `scope` / `scope_label`、`status_labels`（`pass`=达标、`fail`=未达标、`insufficient_data`=数据不足）；
- `thresholds`：回传规范化后的 `items[]`（`item`/`min_avg`）与 `total`（未设为 `null`）；
- `summary`：`contestants` 与三类人数 `pass` / `fail` / `insufficient_data`；
- `contestants[]`（按最终名次排序）：`status`/`status_label`、`rank`、`total`、`total_threshold`、`total_check`（未设总分线为 `null`；数据不足也为 `null`，不判定）、`missing_items`（数据不足时为缺失的**被设门槛**项目列表）、`reasons[]`（`missing_items` / `item_below` / `total_below`，含可读 `message` 与差距），以及 `items[]`——对会话中**每个项目**给出 `avg`（无评分为 `null`）、`has_data`、`threshold`（该项目未设门槛为 `null`）与 `passes`（未设门槛为 `null`）。

`POST /api/sessions/{id}/pending-rank` 请求体：

```json
{
  "item": "技术展示",
  "target": 5,
  "score_min": 0,

```

## 算法说明

- 总分聚合方式为**项目内先对评委求均值，再对项目求和**，因此项目之间等权；如某选手在某项目缺少评委评分，该项目按实际到的评委取均值。
- MAD 标准化只在每个分组内部拟合尺度（中位数/MAD），再统一映射到全局中位数与全局 MAD 的尺度上；校准分可以出现负值或超出原始量程，这是对极端宽/严评委做稳健降权的正常表现。
- 名次使用**竞赛排名**（1,2,2,4，同分并列）。并列组以**本组最高分锚定**成员资格：按总分降序排列后，从每组最高分起，后续成绩与该组锚点之差在 `1e-9` 内才留在同组，一旦相对锚点超出容差即另开下一组，组名次取其首个位置（形如 1、1、3）；**不逐对比较相邻成绩**，避免「甲 90、乙 90−6e-10、丙 90−1.2e-9」式每对相邻都在容差内、但首尾差已超界时的同分链式扩散。同分者按键名稳定排序。原始分、校准分、最终分三套排名及名次反转、待补评分名次边界、权重临界点名次、晋级门槛与同评委可比对照等只读结果统一使用该名次口径。
- 「最终总分」= 对每条评分应用人工裁决（校准分或保留原分）后重新聚合的结果，用于实时排名；原始排名与纯校准排名不受裁决影响，始终保留以便对照。
- **排名稳定性实验**在内存中复制一份评分并剔除被排除评委/项目的全部评分（被剔除评分上的裁决一并忽略），随后用同一套 `analyze` 管线重新拟合分组与全局中位数/MAD 并重新聚合排名，再与基线逐位对比；选手在剩余数据中无任何评分时标记为「无法计算名次」。整个过程不执行任何数据库写操作。
- **双选手对比**直接复用当前 `analyze` 结果中两名选手的项目均分与总分做差（A−B），逐项目按最终分判定领先/持平（差值绝对值 ≤ 1e-9 视为持平）；一方在某项目无评分时该项目标记为「无数据」，不参与差值计算与胜负统计，总分仍按各自实际参评项目汇总。对比在每次请求时重新计算，不写入任何存储。
- **评委排序分歧**是 `analyze` 输出中的 `judge_disagreement` 段，独立于校准管线：直接从原始记录按「项目 × 无序评委对」建索引，只取该对评委在同一项目下都打过分的选手；共评选手不足 2 名的分组标为样本不足，不计入任何汇总。选手对按两位评委的原始分差归类（两人都非平分为同向/逆向，恰一人平分为单方同分，两人都平分为双方同分），可比较对数与逆向占比只统计双方均非同分的选手对。结果**不接收 decisions、不随 scope 变化**，因此上传、合并确认及任何写操作返回的最新分析中它都实时一致，且没有任何接口能通过它修改数据。
- **评委严宽差异诊断**是 `analyze` 输出中的 `judge_offsets` 段（`app/judge_offsets.py` 为纯函数），同样独立于校准管线：以「选手 × 项目」为共评单元，对每对评委收集两人共同评过单元上的原始分差（甲 − 乙），取**中位数**为该对的观测分差、**共评记录数**为拟合权重。评委关系图（节点 = 评委，边 = 有共评记录的评委对）按**连通分量**分解后逐分量解加权最小二乘：最小化 Σ 权重 ×（观测分差 − 偏移量之差）²，法方程为加权拉普拉斯系统，固定分量内首位评委为 0 求解约化正定方程组（部分主元高斯消元），再平移到**分量内零均值**——偏移量因此只是分量内相对值，**不跨分量比较**；没有任何共评边的评委不参与拟合，标为**不可估计**。结果不接收 decisions、不随 scope 变化，随上传、合并确认等写操作返回的最新分析实时刷新，且另有 `GET /api/sessions/{id}/judge-offsets` 只读接口单独获取，不执行任何写操作。
- **批处理规则**对每个评分取全部命中规则，按 `(priority ASC, 规则顺序 ASC)` 选出唯一胜出规则；没有任何规则命中的评分不写入新裁决（保持现状）。应用时规则保存与全部裁决 upsert 在同一事务中提交；重新上传 CSV 会连同裁决一起删除旧规则（评委/项目集合已变），清空会话通过外键级联删除规则。
- **补评分派**把「还需补哪些评分」建模为二分图最大流：源点 → 评委（容量 = 该评委本轮可接任务数），评委 → 需求单元（容量 1，仅当该评委**评过该项目但未评该单元**），单元 → 汇点（容量 = `max(0, 目标人数 − 已有评分数)`）。最大流即分派任务总数最大的方案。为在多个最优并列方案间稳定输出，按固定的**评委 → 项目 → 选手**次序逐条候选边做「强制纳入」可行性测试（强制该边为 1 后仍能补满最优总数则纳入，否则永久放弃），得到的边集在所有最优方案中按该次序字典序最大，因此结果完全确定、可复现。整个计算在内存中完成，**不读写评分、裁决或会话**（`app/backfill.py` 为纯函数）。
- **合并导入**以「选手 + 评委 + 项目」三元组为匹配键：三元组仅出现在新文件→新增，仅出现在当前会话→删除，两侧都有→比较分数判定变更或未变。预览时服务端把解析记录与基线快照存入 `merge_previews` 表并发放一次性标识；确认只凭该标识在单事务内原子消耗标识、取回快照、重建计划并核对基线（含受影响评分的裁决状态），通过后变更行走 `UPDATE`（保留原行 id，使规则与审计引用稳定）并显式删除该行旧裁决，删除行先删裁决再删评分，新增行按新文件顺序追加到 `row_order` 末尾，未变行完全不触碰；`batch_rules` 在整个合并过程中不执行任何写操作。差异计算（`app/merge.py`）是纯函数，预览与确认各自重新计算一次；标识无效/已使用/已过期/跨会话或基线不符均返回 `409`，既无法用过期预览覆盖并发改动，也无法绕过预览写入未预览的记录。
- **项目权重临界点分析**（`app/weight_analysis.py`）是建立在一次 `analyze` 结果之上的只读纯函数：取每位选手在选定项目的**最终均分** `d_c`（缺失项目取 0）与最终总分 `T_c`，其随倍率变化的总分为线性函数 `f_c(w) = d_c·w + (T_c − d_c)`，`w ∈ [0, 上限]`，其余项目倍率恒为 1。对全部选手对枚举直线交点 `w*`（斜率与截距的浮点计算结果**精确比较**：完全相等才算平行；平行且截距也相等即为始终并列，不产生交点），仅保留落在闭区间内的交点；端点吸附、同位置交点归并与区间切分共用 **1e-12 级相对容差**（约机器精度量级）——同一数学交点因浮点运算产生的微小偏差仍归为一处，可表示且真实不同的近邻交点（哪怕间距只有 1e-10 量级）各自成类、分别列出。类内用并查集把相交选手合并成并列组（天然处理三人及以上同时相交），因此每个临界点的并列组**只含在该点真实相等的选手**。端点 0 与上限始终作为区间分隔点：恰好落在端点的交点带 `start`/`end` 标记；任意相邻分隔点（端点或临界点）之间取开区间中点。每个临界点与中点都重新用竞赛排名（1224，同分阈值 1e-9）给出全员名次与总分；临界点并列组的名次按组内均值整体排列以吸收浮点噪声，行内总分仍为各自的仿射计算值。模块不接收写操作；评分、裁决或校准范围变化后由前端重新请求计算。
- **晋级门槛检查**（`app/promotion.py`）是建立在一次 `analyze` 结果之上的只读纯函数：门槛只针对用户列出的项目与最终总分，逐位选手取其在当前校准范围与裁决下的逐项目 `eff_avg` 与 `eff_total`。选手若缺少**任一被设门槛的项目**，直接判为「数据不足」，列出缺失项目，**不把缺失项目按 0 分计入，也不再判定总分线**；其余选手逐项比较均分与最低线（差在 1e-9 内的浮点误差视为相等，即恰好压线算达标），再（可选）比较总分与总分线，任一不过即「未达标」并在 `reasons` 中同时给出全部失败项与具体差距（含可读中文说明）。选手缺少的若是**未设门槛**的项目，不影响判定、总分仍按实际参评项目汇总。模块不执行任何写操作；评分、裁决或校准范围变化后由前端自动重新请求，门槛本身只保留在浏览器页面中，可一键清空。
- **待补评分名次边界**（`app/pending_rank.py`）是建立在一次 `analyze` 结果之上的只读纯函数：对选定项目，每位选手的评分补足至目标评委人数 `target`，每条待补分独立取闭区间 `[score_min, score_max]` 内的任意值。选手在该项目的均分区间为 `(已有最终分之和 + 缺口 × 下/上限) / target`；最终总分区间 = 其余项目现值（当前最终总分 − 该项目当前最终均分，缺失该项目时不减）+ 该项目均分区间。可达到的最好名次 = 本人总分取上限、他人总分取下限构成的总分向量交由主排名函数（锚定并列组、同分容差 `TIE_EPS`）算出的竞赛名次；最差名次同理对调上下限——与主排名完全同一口径，不另做相邻成绩比较。任一选手在该项目的已有评分数超过 `target` 时整个请求被拒绝。模块不执行任何写操作；评分、裁决或校准范围变化后由前端自动重新请求。
- **同评委可比对照**（`app/common_judge.py`）是建立在一次 `analyze` 结果之上的只读纯函数：对每对选手、每个项目，取双方在该项目评委集合的**交集**（共同评委，按全体评委首次出现顺序排列），交集为空即该项目不可比；任一方在该项目没有评分时直接判为「一方缺项目」，同样不可比。对可比项目，分别对**同一组共同评委**的最终分求均值 `a_avg` / `b_avg`，差值 `delta = a_avg − b_avg`（共同评委均分之差，天然不受双方评委覆盖不同与评委间严宽差异影响），并把各可比项目的均分与差值逐项求和得到 `a_comparable_total` / `b_comparable_total` / `comparable_delta`；至少一个可比项目时整对为**可比**，可比领先者按 `TIE_EPS` 判定（差在容差内为持平），全部项目不可比时整对为**不可比**，可比总分字段为 `null`、**不按 0 分处理**。方向对照：**全量口径的领先者、并列与反向一律以当前 `analyze` 的最终名次 `eff_rank` 为准**——`a_rank == b_rank`（主榜锚定并列组，形如 1、1、3）即为 `full_tie`（**全量并列**），不构成反向；名次有先后时，全量领先者（名次靠前者）再与可比领先者比较，两者均非持平且相反才为 `reversed`（**反向**），一致为 `same`；可比总分差持平时按非反向（`same`）处理。**不使用全量总分差 `full_delta` 落 `TIE_EPS` 容差判定全量并列**：锚定组外两人（如名次 1 与 3）的分差可能仍在容差内（90−0.6e-9 与 90−1.2e-9），但名次已有先后，此时不能标为全量并列。`full_delta` 仍作为全量总分差（A−B）数值返回与展示，仅不参与并列/方向判定。明细中保留每个项目双方各自的全部评委最终分（含非共同评委，仅展示、不参与同评委均分），保证差异可追溯。模块不执行任何写操作；评分、裁决或校准范围变化后由前端自动重新请求。

├── Dockerfile
├── docker-compose.yml
